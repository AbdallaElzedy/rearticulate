# Request taxonomy

Sources (verbatim snapshots dated 2026-09-08): Prompting best practices, https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices; Prompting Claude Fable 5.1, https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1; Prompting Claude Fable 5, https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5; Prompting Claude Opus 5, https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5; Prompting Claude Sonnet 5, https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5; Prompting Claude Opus 4.8, https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-4-8. Bracketed IDs resolve in `references/technique-catalog.md` (BP-nnn) and in `references/models/<profile>.md` (F51-nn, F5-nn, O5-nn, S5-nn, O48-nn). Snippet IDs resolve in `references/snippet-library.md`, and the default-path snippets are reproduced verbatim at the end of `templates/rearticulated-prompt.md`.

SKILL.md opens this file when two rows match, when the chosen row has conditional snippets, sub-rows, or an overlay row whose signals fire, when a Step 1c signal other than files-named or domain fires, or when the request involves screen or browser automation, an unattended or notifying agent, a memory store, a review or finder harness, a design-variety brief, or an interactive coding product. It holds four things: the row table Step 1b picks from, the expanded Step 1c signal list, the full anti-pattern conversion list that Step 4 summarises, and the per-model symptom-to-fix summaries.

How a row is used. Step 1b picks exactly one primary row. A second matching row contributes only its mandatory extras, not its whole snippet set; three or more matching rows resolve to agentic long-horizon (SKILL.md Step 1b). A sub-row never stands alone: it is picked with its parent and adds the parent's extras plus its own. The six rows the model pages justify are overlay rows, not primary rows: each attaches to whichever primary row Step 1b picked when its Signals column fires; the parentheses name the primaries each most often accompanies, not a whitelist (code-review harness prompt and interactive coding product with code change, question or assessment, or prompt authoring for another model; design variety brief with frontend or design; asynchronous agent with send_to_user and memory system with agentic long-horizon or prompt authoring; computer use with vision or data extraction or agentic long-horizon), and it contributes its mandatory extras only, like a second matching row. Neither a sub-row nor an overlay row counts toward the three-row rule, which counts primary rows only. A secondary or overlay row's mandatory extras are dropped when the primary row's structure already fixes the deliverable's shape, or when the extra needs a user sample that was not supplied, and the drop is recorded in `Assumed:`. Nothing in a row overrides the target profile: a row names what the request type needs, and the target profile's section 4 and section 5 decide which of those snippets exist for that model. A snippet measured on one page is never grafted to another profile without an `Assumed:` entry saying so (BP-025). When no row matches cleanly, `examples/rearticulations.md` holds nine worked cases to pattern-match against.

Row names. Step 1b's names are canonical here. `technique-catalog.md` and `examples/rearticulations.md` write five of them with a slash, spaced or unspaced: question / assessment, writing / formatting, frontend / design, vision / data extraction, research / info gathering. Those are the same rows as question or assessment, writing or formatting, frontend or design, vision or data extraction, and research, and those files also write code change and long-document analysis hyphenated as code-change and long-document; all are the same rows.

Every row assumes the always-filled tags of `templates/rearticulated-prompt.md`: `role`, `context`, `task`, `constraints`, `output_format`, `success_criteria`, `verification` (omitted only when the target model is Claude Opus 5). The "Mandatory tags and extras" column lists what the row adds on top of those, including the conditional tags `documents`, `examples`, and `execution_guidance`.
